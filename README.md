## Practice workflow

1. Read the linked problem and devise examples before writing code.
2. Describe an approach in plain English, then write my own attempt.
3. Test normal and edge cases and record actual results.
4. Explain time and extra-space complexity in terms of the input size.
5. Record any hints used and lessons learned; revisit the problem later.
6. Commit honest milestones, including unfinished attempts when useful.

Keep solutions and explanations in my own words. Link to original problems instead of copying their statements or editorials. Only mark work complete after implementing and testing it.
